# Tone Guardrail

เอกสารนี้กำหนดกติกาคุมโทนของหน้า learner-facing ใน repo นี้

## เป้าหมาย

- ให้ทุกวิชาที่ generate ออกมาอ่านเหมือนเว็บสำหรับผู้เรียนจริง
- ลดโอกาสที่ข้อความจากฝั่ง tooling หรือ repo หลุดไปอยู่ใน output
- คุมโทนของ placeholder ให้เป็นมิตรและไม่กดดัน แม้ยังไม่ลงรายละเอียดรายวิชาเต็ม

## กฎหลัก

1. หน้า learner-facing ห้ามพูดเหมือนคู่มือระบบ
2. หน้า learner-facing ห้ามเปิดเผยชื่อ tool, file path, schema, หรือศัพท์ทางสถาปัตยกรรมโดยไม่จำเป็น
3. placeholder ต้องอธิบายว่าผู้เรียนจะใช้ส่วนนั้นอย่างไร ไม่ใช่บอกว่าคนทำระบบควรแก้อะไร
4. หน้า `intro` ต้องลดความกดดันและชวนเริ่มต้น
5. หน้า `missions` ต้องอธิบายการประเมินในเชิงช่วยสะท้อนการเรียนรู้ ไม่ใช่ภาษาลงโทษ
6. หน้า `resources` ต้องพูดถึงการใช้งานของผู้เรียน ไม่ใช่ที่มาของไฟล์ manifest

## คำที่ควรหลีกเลี่ยงใน output

- `placeholder`
- `scaffold`
- `init-new-course.mjs`
- `template workflow`
- `canonical source`
- `manifest.json`
- `render`
- `block กลาง`

## สิ่งที่ควรพูดแทน

- จาก `placeholder` -> `ส่วนนี้จะค่อย ๆ เติมรายละเอียดเพิ่มในภายหลัง`
- จาก `scaffold นี้สร้างจาก ...` -> `ส่วนนี้เป็นจุดเริ่มต้นของบทเรียน`
- จาก `source จริงของรายวิชา` -> `เนื้อหาของรายวิชา`
- จาก `block กลางของระบบ` -> `ส่วนสำคัญของหน้า` หรือ `โครงหลักของหน้า`

## ระดับการใช้งาน

กติกานี้ต้องถูกใช้ใน 3 ชั้นพร้อมกัน:

1. `docs`
2. `generator / scaffold`
3. `validator`
